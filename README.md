# Tarkov Server Guard

Escape from Tarkov와 Escape from Tarkov: Arena의 로컬 로그에서 최근 접속 기록을 확인하고, 서버 핑·추정 지역·Windows 방화벽 차단 상태를 조회한 뒤 필요한 서버만 차단하거나 해제하는 Windows 프로그램입니다.

현재 배포 버전은 `v0.7.1`입니다.

## 주요 기능

- 공홈과 Steam의 EFT·Arena 설치 경로를 시작 시 자동 탐색하고, 실제 로그가 가장 최근인 경로를 선택
- 설치 이동 시 `자동 찾기`, 자동 탐지 실패 시 `직접선택` 제공
- 두 게임의 최근 레이드 기록을 한 목록에서 최대 100개 표시
- `최근100개`, `오늘`, `7일`, `30일`, `직접선택` 기간 검색 제공
- `전체`, `EFT`, `Arena` 필터 제공
- 폴더가 아니라 SID 기반의 레이드 단위 기록 생성 및 중복 제거
- EFT 진행 유형을 `PvP`, `PvP시즌`, `PvE(서버)`, `PvE(로컬)`로 구분
- 접속 시각, 성공한 유저신고 횟수, 게임, 맵·게임유형, 서버 IP, 데이터센터 / 추정 지역 표시
- 게임 로그가 기록한 실제 RTT·실게임 패킷손실과 현재 ICMP 핑을 구분해 표시
- 최근 로그 목록에서 각 서버의 `현재 핑`을 바로 비교하고, 선택한 접속 서버 카드는 목록 하단에서 상세 정보를 확인
- 선택한 기록의 서버배정 시간, 서버연결 결과와 합쳐 표시되는 재접속 횟수, 게임버전, 포트, SID와 shortId 표시
- EFT의 BSG 게임런처 적용값과 Arena의 현재 인게임 서버 선택값 및 적용 시각 표시
- 현재 필터에 보이는 모든 고유 IP의 방화벽 상태·핑·지역을 `조회` 한 번으로 확인
- 조회 중에는 같은 버튼이 `취소`로 바뀌어 긴 핑·지역 조회를 중단 가능
- DB-IP Lite City를 PC에 저장해 지역을 로컬 조회하고, 새 월판이 있으면 자동으로 안전하게 교체
- 각 행의 분리된 `차단`·`해제` 버튼에서 현재 상태에 맞는 동작 하나만 활성화
- 기존 `EFT_ExcludeChinaHighPingServer_<IP>` 규칙과 현재 `TarkovServerGuard_Block_<IP>` 규칙 모두 인식
- 로그와 독립적인 `서버차단현황`에서 개별·선택·전체 해제 지원
- 넉넉한 기본 높이의 레이드 메모 창에서 자유메모·닉네임 안내·스크린샷·태그를 위에서 아래로 정돈해 표시하고, 로그 독립형 `메모 보관함` 제공
- 성공한 신고가 있는 행의 `유저신고xN` 텍스트를 눌러 고정된 `유저네임`·`신고사유` 입력란에 별도 로컬 메모 기록
- 첫 실행에서 차단 서버가 매칭됐을 때의 대응 방법을 안내하고, 이후에는 제목 옆 `사용방법` 버튼으로 다시 확인
- 새 안정 버전이 있으면 사용자에게 확인한 뒤 내려받아 적용하고 자동 재시작

## 사용 방법

1. `TarkovServerGuard.exe`를 실행합니다.
2. 자동 탐지된 EFT·Arena 로그 경로를 확인합니다. 설치 위치를 옮겼다면 `자동 찾기`를 누릅니다.
3. 자동으로 찾지 못한 경우에만 해당 게임의 `직접선택`으로 설치 폴더 또는 `Logs` 폴더를 고른 뒤 `적용`을 누릅니다. 경로를 바꾸면 `적용` 버튼만 강조됩니다.
4. `최근100개`, `오늘`, `7일`, `30일`, `직접선택`으로 기간을 정하고 `전체`, `EFT`, `Arena` 중 확인할 목록을 선택합니다.
5. `조회`를 누르면 현재 목록의 고유 서버 IP에 대해 방화벽 상태, 핑, 추정 지역을 확인합니다. 로컬 지역 DB가 없으면 최초 1회 자동으로 준비합니다. 진행 중인 조회는 같은 위치의 `취소`로 중단할 수 있습니다.
6. 원하는 행의 빨간색 `차단` 또는 초록색 `해제` 버튼을 누릅니다.
7. 방화벽 변경 시 표시되는 Windows 관리자 권한 요청을 확인합니다.

Arena 서버의 `차단`을 누르면 탈주 페널티 적용 여부가 확인되지 않았다는 전용 경고가 먼저 표시됩니다. 이 창에서 붉은색 `차단`을 직접 선택한 경우에만 방화벽 변경을 계속하며, 초록색 `취소`, Esc 또는 창 닫기는 변경 없이 끝납니다.

첫 실행에서는 서버 차단 후 게임 화면에서 진행하는 방법이 한 번 자동으로 표시됩니다. 이후에는 프로그램 제목 옆의 `사용방법` 버튼으로 같은 안내를 다시 열 수 있습니다.

`서버차단현황`에서는 앱이 관리하는 현재·v1.1.1 규칙을 로그가 없어도 확인할 수 있습니다. 체크박스로 여러 서버를 선택해 해제하거나, 확인창을 거쳐 전체 해제할 수 있습니다. 일괄 해제의 관리자 권한 요청은 한 번만 표시됩니다.

기간 검색은 화면에 이미 표시된 100개만 다시 거르는 기능이 아닙니다. 선택 기간의 EFT·Arena 로그를 다시 읽은 뒤 중복을 제거하고 최신순으로 정리합니다. 결과가 100개를 넘으면 조건에 맞는 전체 건수와 함께 최신 100개만 표시합니다. `최근100개`는 빠른 시작을 위해 기존의 최근 로그 탐색 범위를 유지합니다.

지역 조회는 DB-IP Lite City MMDB를 `%LOCALAPPDATA%\TarkovServerGuard\DbIpLite`에 저장해 처리합니다. 월간 압축 다운로드는 약 60~70MB이고 해제 DB는 약 130MB입니다. 월별 크기는 달라질 수 있으며, 직전 정상본까지 보관하면 저장공간은 약 260MB가 됩니다. 안전한 교체를 위한 다운로드·해제 임시 파일과 원자 교체 과정 때문에 갱신 중에는 일시적으로 약 500MB의 여유 공간이 필요할 수 있습니다. 갱신은 기존 DB를 사용하는 조회를 막지 않으며, 다운로드·검증·교체에 실패하면 직전 정상 DB를 계속 사용합니다. DB-IP Lite는 무료 축소판이므로 도시 정보가 누락되거나 실제 데이터센터 위치와 다를 수 있습니다.

접속 시각 뒤의 말풍선 메모 아이콘을 누르면 해당 레이드의 자유메모·태그·스크린샷을 저장할 수 있습니다. 메모 창은 내용을 보기 쉽도록 기본 높이를 넉넉하게 잡았습니다. 자유메모 상단의 회색 예시와 하단의 `유저닉네임 1·2·3` 양식은 클릭하거나 입력하면 사라지는 안내일 뿐 메모 내용으로 저장되지 않습니다. 이어지는 스크린샷 영역에는 첨부·열기·폴더 열기·첨부 해제 버튼이 한 줄로 정렬됩니다. 스크린샷 원본은 복사하거나 업로드하지 않고 선택한 로컬 파일의 경로만 연결합니다. `메모 보관함`에서는 원본 게임 로그를 삭제한 뒤에도 일반 레이드 메모와 유저신고 메모를 함께 열거나 삭제할 수 있습니다.

성공한 유저신고가 표시된 행에서는 `유저신고xN` 텍스트를 눌러 일반 레이드 메모와 구분된 신고 메모를 열 수 있습니다. 각 신고에는 `1. 유저네임:`과 `신고사유:`가 고정 라벨로 표시되고 입력값만 편집됩니다. 신고 대상과 상황은 사용자가 직접 적는 로컬 기록이며, 프로그램이 닉네임·ID·사유를 게임 로그에서 추정하거나 자동으로 채우지 않습니다. v0.6.6 자유 형식 신고 메모가 있으면 별도 기존 메모 영역에 원문을 보존합니다.

비활성화된 `차단`·`해제` 버튼도 클릭할 수 있으며, 조회 전인지, 이미 차단된 상태인지 등 현재 사용할 수 없는 이유를 안내합니다. 자동 5초 갱신은 사용하지 않습니다. 새 로그를 읽으려면 `적용`을 다시 누릅니다.

## 표시 정보의 의미

- `현재 핑`: 앱이 지금 ICMP로 측정한 값입니다.
- `실게임 RTT`: 게임의 `network-connection` 로그가 연결 중 기록한 RTT입니다. 로그에 없으면 `-`로 표시합니다.
- `실게임 패킷손실`: 같은 게임 네트워크 로그가 실제 연결 중 기록한 손실률입니다. 현재 ICMP 핑 손실률이 아닙니다.
- `서버배정`: 매칭 전체 시간이 아니라, 로그에서 서버 배정까지 확인된 시간을 뜻합니다.
- `유저신고xN`: `backend` 로그에서 성공 응답까지 확인된 `/client/report/send` 요청 수입니다. 텍스트를 누르면 별도 로컬 신고 메모를 열 수 있습니다. 신고 대상 닉네임·ID·사유는 로그에 없어 추정하지 않으며, 메모 내용은 사용자가 직접 입력합니다.
- `서버연결 결과 · 재접속`: 마지막 서버 연결 구간의 네트워크 결과와, 최초 연결 이후 같은 레이드에 기록된 추가 `Connect` 시도 수를 한 셀에 함께 표시합니다. 탈출·도주·미아·사망 같은 레이드 결과는 아닙니다. 각 셀에 마우스를 올리면 상태별 의미를 확인할 수 있습니다.
  - `정상종료`: 연결 성공 뒤 정상 종료 사유가 기록됐습니다.
  - `접속실패 · 시간초과`: 연결이 완료되기 전에 시간 초과가 기록됐습니다.
  - `비정상종료 · 시간초과`: 연결 성공 뒤 시간 초과로 연결이 끝났습니다.
  - `접속실패`: 연결 성공 전에 종료됐습니다.
  - `비정상종료`: 연결 성공 뒤 정상 종료가 아닌 명시적인 종료 사유가 기록됐습니다.
  - `종료미확인`: 진행 중, 강제 종료, 로그 누락 등으로 종료 상태를 확정할 수 없습니다.
  - `접속기록 없음`: 서버 IP는 배정됐지만 대응하는 `Connect` 로그가 없습니다.
  - `해당 없음`: 로컬 PvE라 연결할 게임 서버가 없습니다.
- EFT의 `Regular`, `Pve`, `PvpSeason`과 서버 연결 증거를 함께 사용해 게임유형을 표시합니다. IP 누락만으로 로컬이라고 추정하지 않습니다.
- `게임런처 선택 서버`: EFT는 BSG 게임런처 로그에서 마지막으로 확인된 적용값을, Arena는 인게임 `Regions.ini`의 현재 선택값을 표시합니다. 자동 선택이 켜져 있으면 `자동 선택`, 확인할 기록이나 설정이 없으면 `선택 기록 없음`으로 표시합니다.

## 핑 색상 기준

- 100ms 미만: 초록색
- 100ms 이상 150ms 미만: 노란색
- 150ms 이상: 빨간색
- 응답 없음 또는 미측정: 회색

ICMP 손실률은 표시하지 않습니다. `실게임 패킷손실`은 게임 로그 값이며, ICMP 무응답만으로 서버가 차단됐다고 추정하지 않습니다. Windows 방화벽의 관리 대상 규칙을 직접 확인했을 때만 `차단 중`으로 표시합니다.

## 개인정보 및 네트워크

- 게임 로그, EFT 런처 로그, Arena 지역 설정은 로컬에서만 읽으며 자동 업로드나 제보 기능이 없습니다.
- 프로필 ID 등 계정 식별자는 파싱하거나 표시하지 않습니다.
- 유저신고 로그 분석에서는 요청 시각과 성공 횟수만 사용하며 신고 대상 닉네임·ID·사유를 로그에서 파싱하거나 자동 저장하지 않습니다.
- 유저신고 메모에는 사용자가 입력한 내용과 보관함 표시에 필요한 게임·맵·레이드 시각·성공 신고 건수만 기기에 저장합니다. 게임 로그 원문·계정 ID·SID·로컬 경로는 저장하거나 전송하지 않습니다.
- 첫 실행 안내 여부는 `%LOCALAPPDATA%\TarkovServerGuard\usage-guide.shown` 빈 파일로만 로컬에 기록하며 외부로 전송하지 않습니다.
- 메모는 `%LOCALAPPDATA%\TarkovServerGuard\RaidNotes`에 보관됩니다. 스크린샷은 로컬 경로만 저장하며 원본을 복사·삭제·업로드하지 않습니다.
- 차단 중인 서버의 데이터센터·추정 지역·차단 시각은 로그가 삭제돼도 `서버차단현황`에서 확인할 수 있도록 `%LOCALAPPDATA%\TarkovServerGuard\blocked-server-metadata.json`에 로컬 저장하며, 해제에 성공한 서버 정보는 함께 삭제합니다.
- 별도의 BSG 런처 설정 파일은 읽지 않습니다. EFT는 런처 로그의 `selectedGame`과 서버 적용 이벤트만 해석하며, 같은 줄의 인증·계정 필드는 해석·저장·전송하지 않습니다. Arena는 인게임 `Regions.ini`의 지역명·선택 상태·자동 선택 여부와 파일 수정 시각만 사용합니다.
- Steam 탐지 시 설치 루트의 `libraryfolders.vdf`와 공식 EFT AppID `3932890`의 설치 manifest에서 경로 항목만 읽습니다. Steam 계정·사용자·인증 파일은 읽지 않습니다.
- `조회`는 현재 핑을 확인하기 위해 각 게임 서버에 ICMP 요청을 직접 보내지만, 지역 판별은 PC에 저장된 DB-IP Lite City로 처리합니다. 게임 서버 IP를 DB-IP.com이나 다른 외부 지역 조회 API에 전송하지 않습니다.
- 최초 준비와 월간 갱신 때 `download.db-ip.com`에서 압축 지역 DB 파일을 내려받습니다. 월간 약 60~70MB이며 월별로 달라질 수 있습니다. 일반 HTTPS 다운로드와 마찬가지로 사용자의 공인 네트워크 IP와 앱 User-Agent는 다운로드 서버에 보일 수 있지만, 게임 서버 IP·게임 로그·계정 정보·SID·로컬 경로는 요청에 포함하지 않습니다.
- 설치형·Velopack 포터블 빌드는 앱 UI가 열린 뒤 하루에 한 번 이하로 `github.com`의 공식 `Spirit-Schema/tarkov-server-guard` Releases를 확인합니다. 일반 HTTPS 요청과 마찬가지로 사용자의 공인 네트워크 IP와 앱 요청 정보는 GitHub에 보일 수 있지만, 게임 서버 IP·게임 로그·계정 정보·SID·로컬 경로는 요청에 포함하지 않습니다. 새 안정 버전이 있을 때만 `업데이트`·`나중에`를 표시하며, `나중에`는 같은 버전 알림을 24시간 미룹니다.
- 지역 DB는 `%LOCALAPPDATA%\TarkovServerGuard\DbIpLite`에 저장되고, 손상되거나 예상 형식이 아닌 파일은 활성화하지 않으며 직전 정상본을 보존합니다.
- 로그 탐색과 방화벽 상태 조회에는 관리자 권한이 필요하지 않습니다.
- `차단` 또는 `해제`를 실행할 때만 Windows 방화벽 변경 권한을 요청합니다.
- 해제는 관리 대상 이름, 방향, 동작, 프로토콜, 단일 원격 IP가 모두 일치하는 규칙만 삭제합니다.
- 패킷 캡처, 게임 메모리 접근, 게임 파일 수정은 하지 않습니다.

이미 배정된 서버를 차단하면 `Server Connection Lost`가 발생할 수 있습니다. 차단은 해당 레이드에 재접속하기 위한 기능이 아니라, 나간 뒤 다시 매칭할 때 그 IP로의 새 아웃바운드 연결을 막기 위한 기능입니다.

## 실행 환경과 배포 형태

- Windows 10 또는 Windows 11
- .NET Framework 4.8
- 최초 지역 DB 준비와 자동 업데이트 확인을 위한 인터넷 연결
- 지역 DB 갱신 중 최대 약 500MB의 여유 공간 권장

권장 배포본은 `SpiritSchema.TarkovServerGuard-win-Setup.exe`입니다. 사용자별 설치를 사용하므로 앱 업데이트 자체에는 관리자 권한이 필요하지 않습니다. `SpiritSchema.TarkovServerGuard-win-Portable.zip`도 사용할 수 있으며 압축을 푼 폴더 안의 파일 구성을 유지해야 합니다. 실행 파일은 현재 코드 서명이 없어 Windows SmartScreen에서 `알 수 없는 게시자` 안내가 표시될 수 있으므로, GitHub 공식 Releases의 SHA-256과 내려받은 파일을 대조하는 것을 권장합니다.

자동 업데이트 확인·다운로드·적용 중 오류가 나면 현재 설치본을 유지하고 앱의 다른 기능은 계속 사용할 수 있습니다. 사전 릴리스, 같은 버전, 이전 버전은 자동 업데이트 대상으로 사용하지 않습니다.

## 빌드 및 테스트

Windows PowerShell에서 다음을 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

.NET Framework 4.8에 포함된 C# 컴파일러로 개발용 실행 파일을 만들며, 이 단계에는 별도 SDK나 NuGet 패키지가 필요하지 않습니다. 합성 EFT·Arena·런처 로그와 Arena 지역 설정, 기간 경계, 방화벽 입력, MMDB 파싱·갱신·복구, GitHub 업데이트 판단 검증 테스트를 함께 실행합니다. 개발용 단일 EXE 옆에 Velopack 런타임이 없으면 자동 업데이트만 안전하게 비활성화됩니다.

실제 자동 업데이트 가능한 검토·배포 패키지는 다음 명령으로 만듭니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\package-release.ps1 -Version 0.7.1
```

패키징 도구 실행에는 .NET 8 런타임이 필요합니다. 이 스크립트는 SHA-256으로 고정 검증한 Velopack 1.2.0과 Newtonsoft.Json 13.0.4를 빌드 캐시에 준비하고, 실제 런타임 연결 테스트 후 Setup·Portable·업데이트 feed를 `build\Releases-v0.7.1`에 생성합니다. 사용자 검토용 파일은 `review\TarkovServerGuard-v0.7.1`에 따로 만들어 현재 실행 중인 검토본을 덮어쓰지 않습니다. GitHub Releases에는 같은 실행 파일 ZIP만 임의로 올리는 것이 아니라, 이 폴더의 `releases.win.json`, `.nupkg`, Setup과 Portable 자산을 함께 게시해야 자동 업데이트가 작동합니다.

검토 폴더 최상위의 `TarkovServerGuard.exe`는 설치 없이 기능을 빠르게 확인하는 개발용 실행 파일입니다. 실제 자동 교체 흐름은 `Velopack-Release` 안의 Setup 또는 Portable을 사용해야 활성화됩니다.

UI 샘플은 다음 명령으로 확인할 수 있습니다.

```powershell
.\dist\TarkovServerGuard.exe --demo
```
